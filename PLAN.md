> Итог интервью. Тридцать два решения, принятых явно.
> Код по этому документу ещё **не написан** — сначала сверка.

## 1. Задача

Курс между двумя валютами, между которыми нет прямого обмена, считается через доллар.
Рубли → доллары → донги. Пользователь вводит **свои реальные курсы** (те, по которым
ему меняют в конкретном месте) и получает **свой реальный курс** пары.

Приложение личное, local-first, без бэкенда, работает офлайн.

## 2. Модель (Q2a)

Звезда с USD в центре. У каждой валюты ровно одно число — **сколько её единиц за 1 $**.

```
a = единиц валюты A за 1 $   (отдаю)
b = единиц валюты B за 1 $   (получаю)

номинальный курс:  1 A = b / a  единиц B
обратный:          1 B = a / b  единиц A
```

Валюта как сущность в приложении **не существует** — есть две позиции (отдаю / получаю)
и два числа. Справочник валют, домашняя валюта, список сохранённых — всё отвергнуто
(Q13, Q14): курс протухает, и тапнуть по сохранённому значению не дешевле, чем поправить
предзаполненное.

## 3. Комиссия (Q7b, Q9b)

Одно поле на всю цепочку, переключатель **`%` / фикс**.

- **Процент** `p` меняет курс и не зависит от суммы.
- **Фикс** `F` номинирован **всегда в валюте, которую отдаёшь**, выбора нет.

```
сумма X валюты A →

  процент:  Y = X * (b / a) * (1 - p)
  фикс:     Y = (X - F) * (b / a)

эффективный курс (единиц B за 1 A):  Y / X
```

Ключевое следствие, принятое сознательно: **при фиксе «мой реальный курс» — функция
от суммы.** Строки курса пересчитываются, пока печатаешь сумму. Это не побочный
эффект, это и есть смысл: видно, с какого объёма фикс перестаёт быть грабежом.

Краевые случаи:

| Ситуация | Поведение |
|---|---|
| Сумма пуста или 0 | Показываем **номинальный** курс, помечаем «без учёта комиссии» |
| `X <= F` | «Комиссия съедает всю сумму», результат не показываем |
| `a = 0` или `b = 0` | Прочерки, без `NaN` и `Infinity` |
| Поля не заполнены | Прочерки + подсказка «введите оба курса — увидите результат» (Q15) |

## 4. Отображение результата (Q4 a+c, Q11a)

Три строки, сверху вниз по важности:

1. **Сумма** — главный результат. `500 000 ₫ → 1 730 ₽`
2. **Курс туда** — `1 000 ₫ = 3,46 ₽`
3. **Курс обратно** — `1 ₽ = 289 ₫`

### Автомасштаб

Жёсткой константы «за 1000» нет — она вычисляется, потому что конвенция зависит
не от валюты, а **от пары** (для VND↔RUB естественно «за 1000», для VND↔IDR — «за 1»).

```
s = наименьшая степень 10 из {1, 10, 100, ...}, при которой  v * s >= 1
показываем:  "s A = (v * s) B"
потолок s = 10^6
```

### Знаки после запятой

Выводятся из порядка величины, справочник валют для этого не нужен:

```
|x| >= 1000  → 0 знаков
|x| >= 1     → 2 знака
иначе        → 4 знака
```

## 5. Интерфейс (Q17b, Q18b, Q27 a+b, Q28a)

**Ядро всегда на экране:**

- поле «Отдаю, за 1 $» + необязательный текстовый ярлык (`₽`, `рубли` — что угодно)
- поле «Получаю, за 1 $» + такой же ярлык
- блок результата (три строки выше)

**Свёрнуто в «Дополнительно»** — раскрывается автоматически, если значения уже заданы:

- сумма
- комиссия + переключатель `%` / фикс

**Подписи и ярлыки (Q27).** Позиционные подписи есть всегда — «Отдаю» / «Получаю».
Ярлык необязателен, вводится один раз, уезжает в ссылку. С ним результат перестаёт
быть безымянным: `1 000 ₫ = 3,46 ₽` вместо `1 000 = 3,46`.

**Ввод чисел (Q28a).** `inputmode="decimal"`, принимаем точку и запятую, **на лету
ничего не форматируем** — разделители сдвигают каретку и ломают правку середины числа.
Под полем серое эхо `26 400` для проверки порядка величины.

**Свежесть (Q18b).** Поля предзаполнены прошлыми значениями, под ними — «введено
3 дня назад». Ценность не в актуальности числа, а в том, что его дешевле поправить,
чем набрать; отметка снимает ложное доверие.

## 6. Хранение и перенос (Q10b, Q3a)

**URL-хеш — источник правды.** Курсы, ярлыки, сумма, комиссия и метка времени
кодируются в адрес. Кнопка «скопировать ссылку» решает разом три задачи: бэкап,
перенос на другое устройство, шаринг.

`localStorage` — быстрый кэш для предзаполнения, не более.

Причина такого выбора — факт: iOS с 13.4 чистит `localStorage` после 7 дней
без взаимодействия. PWA на домашнем экране формально выведены из-под правила,
но гарантии Apple не даёт, а профиль использования у приложения худший из возможных:
активно в поездке, потом месяцы тишины.

**Курсы вводятся только руками (Q3a).** Никаких API. Смысл — «мой курс», а не рыночный;
плюс ноль сетевых запросов в рантайме.

## 9. Тесты (Q26a)

Покрываем **только `src/core/`**. Почти вся ценность продукта — четыре чистые функции,
а UI это три `<input>`; тесты на инпуты проверяли бы React, а не нас.

Обязательный минимум:

- кросс-курс в обе стороны — **перепутанное направление деления самая вероятная
  и самая незаметная ошибка в этом приложении**
- процент и фикс по отдельности
- `X = 0` → эффективный курс не определён, отдаём номинальный
- `X <= F` → комиссия съедает сумму
- `a = 0` / `b = 0` → без `NaN` и `Infinity`
- выбор масштаба: `0,00346 → «1 000 = 3,46»`, `289 → «1 = 289»`
- знаки после запятой на границах 1 и 1000
- round-trip разбора URL-хеша

## 10. Оформление (Q29a, Q31a, Q32a)

Токены копируются из `~/Documents/GitHub/alexeycorr.dev/src/styles/colors.scss`
и переводятся в нативный CSS: **oklch**, акцент hue 280, шкала отступов кратно 8.

Отклонение от исходника: там тема переключается атрибутом `[data-theme]`
(`auto`/`light`/`dark`), здесь переключателя нет — светлая на голом `:root`,
тёмная в `@media (prefers-color-scheme: dark)`.

**Шрифты — самохостинг** (`public/fonts/*.woff2`, в precache; `globPatterns`

- **Ubuntu** — текст
- **JetBrains Mono** — числа. Не эстетика, а **tabular figures**: число в результате
  меняется на каждое нажатие клавиши, и в пропорциональном шрифте строка дёргалась бы
  при смене `1` на `8`
- **Dela Gothic One** не берём — дисплейный шрифт на экране без заголовков

| Telegram-бот на Cloudflare | Технически проходит (100k запросов/день бесплатно), но чат — плохой UI для формы с живым пересчётом |

## 13. Отклонения, всплывшие при реализации

Всё, что было решено выше, реализовано. Ниже — четыре места, где план пришлось
уточнить фактами из кода, а не из разговора.

| Что | Почему |
|---|---|
| `Date.now()` вынесен в модульную константу `OPENED_AT` | Линт React Compiler запретил нечистый вызов в рендере — ровно та польза, ради которой компилятор и брали (Q22). Сценарий «открыл → посмотрел → закрыл» делает зафиксированное на старте время честнее живого таймера |
| В `--font-mono` после JetBrains Mono добавлен Ubuntu | В сабсетах моноширинного нет `latin-ext`, где живут `₽` (U+20BD) и `₫` (U+20AB). Без фолбэка их рисовал системный шрифт, и в строке результата это бросалось в глаза |
| Конфиг react-hooks берётся из `configs.flat['recommended-latest']` | У `configs['recommended-latest']` формат eslintrc (`plugins` массивом строк), и `tseslint.config()` его не принимает |
| Добавлен слушатель `hashchange` | Присланную ссылку могут открыть в уже запущенном приложении — тогда перезагрузки нет и начальное чтение хеша не срабатывает. Собственный `replaceState` события не порождает, цикла не возникает |

Шрифты лежат в `src/styles/fonts/`, а не в `public/`: так Vite сам подставляет
префикс `/usd-bridge/` и хеширует имена.

## 14. Ревизия интерфейса

Три претензии по итогам первого прогона — все обоснованные.

**«Отдаю» / «Получаю» были ложью.** Подписи обещали количество, а в поле лежит
курс: под «Получаю» стояло `26000`, хотя никаких 26 000 пользователь не получает.
Заменено на **«У меня» / «Меняю на»** — они описывают валюту, а не сумму,
и остаются верными при любом содержимом поля.

**Обозначение валюты стояло не на своём месте.** Оторванный от числа серый
прямоугольник под полем не читался, пока в него не ткнёшь. Перенесён внутрь
строки, сразу за число, — теперь строка читается как утверждение
**«90 ₽ за 1 $»**, и назначение слота видно из позиции. Плейсхолдеры числа
и обозначения складываются в готовый пример, поэтому пустая форма сама
показывает, что от неё хотят.

**Двойной контур при фокусе** — ошибка в CSS: кольцо рисовал
`.field__row:focus-within`, и одновременно глобальный `:focus-visible` вешал
outline на сам `<input>` внутри. Внутренние контуры сняты, кольцо на строке
осталось единственным индикатором.

Попутно:

- Числа выровнены по правому краю — так они прижаты к своей единице измерения,
  а порядки величин в соседних строках сопоставимы.
- Между плечами обмена появился шов с подписью **«через доллар»**: тезис
  приложения стоит ровно там, где происходит переход.
- Переключатель `%` / `фикс` переехал внутрь строки комиссии — тот же приём,
  что и с обозначением валюты: после числа стоит то, что объясняет число.
  Заодно ушёл костыль `padding-bottom: 30px`, из-за которого переключатель
  вылезал за карточку.
- При фиксе подпись показывает валюту: **«Комиссия, ₽»** — иначе «200» ни о чём
  не говорит. У процента единица измерения написана на кнопке.

## 15. Валюта: выбор вместо ввода

Текстовое поле для обозначения валюты убрано целиком. Две причины, вторая важнее.

**Символ невозможно набрать.** `₫` отсутствует на всех раскладках клавиатуры
iPhone. То есть на основном устройстве свободный ввод не был неудобным —
он не работал.

**Подпись расходилась с курсом.** Поставил `₫`, приехал в Таиланд, вбил 33 —
приложение уверенно заявляет «1 ₽ = 2,7 ₫». Стирать подпись руками пользователь
справедливо не хочет, а забыть её обновить — легко.

### Список

Берётся целиком из платформы, своей таблицы нет:

- `Intl.supportedValuesOf('currency')` — 162 кода ISO 4217
- `Intl.DisplayNames(['ru'])` — «вьетнамский донг», «грузинский лари»
- `Intl.NumberFormat` с `narrowSymbol` — знаки; у 101 валюты свой, у 61 его нет
  и подписью служит код

Это **ноль байт собственных данных** и ноль риска устаревания. Первой группой
идут 12 частых валют, чтобы не крутить колесо; первым пунктом — «без обозначения».

Селект нативный (штатное колесо iOS), но прозрачный поверх span'а: иначе
в свёрнутом виде торчало бы «₽ · российский рубль» вместо `₽`.

### Правило очистки

Смена валюты — это заявление, что здесь теперь другая валюта, и прежнее число
к ней не относится. Поэтому **замена одной валюты другой стирает курс этого
плеча** (`applyCurrency` в `src/core/state.ts`, под тестом).

Стирание происходит только при настоящей замене:

| Действие | Курс |
|---|---|
| `₫` → `฿` — другая страна | стирается |
| ничего → `₽` — подписали введённый курс | остаётся |
| `₽` → ничего — сняли обозначение | остаётся |
| `₽` → `₽` — выбрали то же самое | остаётся |

### Хранение

`AppState.giveCurrency` / `receiveCurrency` хранят **код ISO 4217**, а не символ.
Символ выводится из кода при отображении, поэтому подпись не может разойтись
с выбором. Значение, не похожее на код (старые ссылки хранили сам символ),
показывается как есть и добавляется в список отдельным пунктом — такие ссылки
продолжают работать.

### Своп

Кнопка в шве «через доллар» разворачивает обмен: переставляются курсы и валюты.
Сумма и комиссия остаются — они заданы в отдаваемой валюте, и пересчитывать их
значило бы решать за пользователя, что он имел в виду («я перепутал местами»
и «меняю обратно на ту же сумму» требуют противоположного). Подписи сами
покажут новую валюту, так что подмены втихую не происходит.

### Отступы

`max(отступ, env(safe-area-inset-*))` заменён на сложение. `max()` выбирал
большее из двух: внизу получалось 34 px — ровно под домашний индикатор
и ничего сверх того, поэтому нижняя кнопка уезжала под панель Safari.

```css
background-size: 28px 28px;
```

Токен `--dot-color` добавлен в обе темы теми же значениями, что в исходнике.

Одна правка поверх исходника: блок результата раньше был залит полупрозрачным
`--accent-glow`, и точки просвечивали сквозь главный элемент экрана. Теперь под
ним непрозрачная подложка `--card-bg-color`, а акцентный оттенок лежит сверху
отдельным слоем `linear-gradient`. Остальные карточки и так непрозрачны.

Побочный эффект, оказавшийся полезным: на широком экране точки заполняют поля
по бокам, и колонка перестала выглядеть потерянной в пустоте.
